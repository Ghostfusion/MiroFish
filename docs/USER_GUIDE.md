# MiroFish 使用手册（零基础版）

> 这份手册写给**不会写代码**的使用者。照着做就能让 MiroFish 帮你「推演未来」。
> 更硬核的说明请看 [`README.md`](../README.md) 和 [`docs/DESIGN.md`](DESIGN.md)。

---

## 1. MiroFish 是什么

你可以把 MiroFish 想成一个**沙盘推演机**：

1. 你给它一份资料（新闻、报告、小说、政策草稿……PDF/MD/TXT 都行）；
2. 再用一句大白话说明你想推演什么（例如「如果武汉大学发布撤销某处分的公告，舆论会怎么走？」）；
3. 它会自动「造」出一个平行世界：把资料里的人物、机构、话题变成成百上千个**虚拟角色**，让他们在一个类似微博/论坛的环境里互相发帖、评论、点赞、转发；
4. 跑完之后，它会给你一份**预测报告**，你还可以**直接和任意一个虚拟角色对话**，问他们「你为什么会这么想」。

它不预测天气，也不炒股保收益。它的价值在于：**把「万一……会怎样」在零风险的环境里先演一遍**。

## 2. 开始之前你需要准备什么

| 需要的东西 | 说明 |
| --- | --- |
| 一台电脑 | Windows / macOS 都可以，建议 8GB 以上内存 |
| 能上网 | 全程需要联网（模型和记忆图谱都在云端） |
| 两个「钥匙」（API Key） | ① **大模型 Key**：推荐阿里云百炼的 `qwen-plus`（[开通地址](https://bailian.console.aliyun.com/)）② **Zep Cloud Key**：免费额度就够试用（[开通地址](https://app.getzep.com/)） |
| 一定的耐心 | 一次完整推演通常需要 10 分钟到 2 小时不等，取决于文档长度和轮次 |

> 关于花费：两个平台都是「用多少付多少」。按官方说明，**一次常规模拟平均约 5 美元**（大模型 + Zep 用量），免费额度可以先跑很小的例子试试。

如果不会申请 Key，可以把这份手册转给身边懂电脑的同事，或到项目主页开一个 Issue 求助。

## 3. 安装（只需做一次）

### 方式 A：一键脚本（推荐，交给懂电脑的人操作一次）

1. 安装三个基础工具：**Node.js 18 或更高**、**Python 3.11 或 3.12**、**uv**（Python 的包管理器）。
2. 把项目文件夹（或从 GitHub 下载的压缩包）解压到任意目录，例如 `D:\MiroFish`。
3. 在该目录里打开「终端 / PowerShell」，依次执行：

```bash
cp .env.example .env      # Windows 用 copy .env.example .env
```

用记事本打开新建的 `.env`，把两个 Key 填进去（其余保持不动）：

```env
LLM_API_KEY=你的大模型Key
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL_NAME=qwen-plus
ZEP_API_KEY=你的Zep Key
```

然后执行：

```bash
npm run setup:all   # 安装所有依赖（第一次会比较慢）
npm run dev         # 启动服务
```

看到提示后，用浏览器打开 **http://localhost:3000** 就能看到界面了。

> 想关闭：回到终端窗口按 `Ctrl + C`。

### 方式 B：Docker（如果电脑上装了 Docker）

```bash
docker compose up -d
```

同样把 `.env` 放在项目根目录，然后打开 **http://localhost:3000**。

### 界面语言

右上角可以切换 **中文 / English**，默认是中文。

## 4. 五步走：从资料到预测报告

整个流程在界面上是 5 个步骤，页面顶部的进度条会显示你现在在哪一步：

```
① 图谱构建 → ② 环境搭建 → ③ 开始模拟 → ④ 报告生成 → ⑤ 深度互动
```

### 第 0 步：上传资料（首页）

- 「**01 / 现实种子**」：把文件拖进虚线框（或点击选择文件）。支持 **PDF、MD、TXT**，可以一次拖多份，单份不要超过 50MB。
  - 小技巧：资料越「有信息量」越好。一篇完整的新闻报道或研究报告，比十句口号有用得多。
- 「**02 / 模拟提示词**」：用大白话写清你想推演什么。例如：
  - 「如果武汉大学发布撤销肖某处分的公告，会引发什么舆情走向？」
  - 「如果这部小说里的主角没有离开，结局会怎样？」
- 点击右下角的「**启动引擎**」。

---

### 第 ① 步：图谱构建

这一步做两件事：

1. 「**本体生成**」——系统读你的资料，自动总结出「有哪些类型的人 / 机构 / 话题，它们之间可能有什么关系」。
2. 「**GraphRAG 构建**」——把资料切成小段，建成一张**知识图谱**（可以理解为「人物关系 + 事件脉络」的资料库）。

界面左侧会实时画出这张图谱（实体节点、关系边），右下方日志里会滚动过程信息。

- 大约需要 **1～5 分钟**。
- 完成后会出现按钮「**进入环境搭建**」，点它继续。

> 如果卡住不动，先看右下角日志里的提示；常见原因是 Key 填错或余额不足。

---

### 第 ② 步：环境搭建

这一步是 MiroFish 最核心的「造世界」：

| 界面上的模块 | 它在做什么（白话版） |
| --- | --- |
| **模拟实例初始化** | 新建一个世界，把参数模板准备好 |
| **生成 Agent 人设** | 从图谱里挑出人物/机构，给每个「角色」写人设、职业、性格、立场、影响力 |
| **生成双平台模拟配置** | 设定世界的时间流速、每个角色几点活跃、发帖频率、推荐算法、话题热度等 |
| **初始激活编排** | 设定世界一开始要发生什么（初始帖子、热点话题、叙事方向） |

你可以直接使用系统的智能设置，也可以在「**模拟轮数设定**」里切到「**自定义**」：

- **强烈建议第一次使用选「自定义」并减少轮数**，这样能快速预览效果、也最不容易报错。
- 界面会提示：若 Agent 规模为 100，预计耗时约多少分钟。轮数越多，时间越长。

准备好之后，点击「**开始双世界并行模拟**」，进入下一步。

---

### 第 ③ 步：开始模拟

这是「世界真正跑起来」的阶段：

- 界面上有两块进度卡：**世界1 / 信息广场**（对应 Twitter 风格）和 **世界2 / 话题社区**（对应 Reddit 风格），各自显示轮次、动作数、模拟时间。
- 下方是实时动作流：谁发了什么、谁点赞了谁、谁关注了谁，一目了然。

你可以：

- 打开「**开启图谱实时刷新 (30s)**」，观察角色行为如何写回知识图谱；
- 随时点「**停止模拟**」；
- 跑到你满意（或全部结束）后，点「**开始生成结果报告**」。

> 首次体验建议：轮数少一点，先看效果，再逐步加大规模。

---

### 第 ④ 步：报告生成

- ReportAgent 会像一位分析师那样，一边「翻资料」一边写报告：检索相关事实 → 分析因果 → 写成一个个章节。
- 报告是**边写边出**的：已经写好的章节会立刻出现在页面上，不需要等全部完成。
- 右侧的实时日志（Agent 日志 / 控制台日志）会显示它在调用什么工具、查到什么。
- 完成后可以点「**进入深度互动**」，也可以等下次从「推演记录」里回来看这份报告。

---

### 第 ⑤ 步：深度互动

三种玩法：

1. **与 Report Agent 对话**：就报告内容追问，例如「哪一类人最可能反对？」
2. **与模拟世界中的任意个体对话**：挑一个角色，问他「你为什么会这么想？」「你周围的人怎么看？」
3. **发送问卷调查到世界中**：勾选多个角色，把同一个问题一次性发给他们（适合做「群体观点抽样」）。

> 注意：**对话和问卷都要求模拟正在运行**。如果模拟已经结束或你关掉了环境，请从「推演记录」重新回到这一步并重新启动模拟。

## 5. 「推演记录」：找回以前的结果

首页可按「推演记录」进入历史列表，每条记录有四个入口：

| 入口 | 能做什么 |
| --- | --- |
| **图谱构建** | 回看当时建出的知识图谱 |
| **环境搭建** | 回看人设和模拟配置 |
| **分析报告** | 打开曾经生成的报告 |
| **开始模拟 / 深度互动** | 需要在运行中启动，不支持历史回放（界面会有提示） |

## 6. 常见问题（对照处理）

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 启动后提示「配置错误」 | `.env` 里两个 Key 没填 | 检查 `LLM_API_KEY`、`ZEP_API_KEY` |
| 点「启动引擎」后一直转圈 | 文件太大 / 网络慢 / Key 无效 | 换小一点的文件；确认 Key 有额度；看终端里的报错 |
| 图谱构建失败 | 文档内容太短或全是图片 | 换一份有正文文字的资料（扫描版 PDF 需要先做文字识别） |
| 环境搭建一直不完成 | 需要生成的人设太多 | 等一会儿；或减少实体数量后重试 |
| 模拟启动后马上失败 | 轮数过多 / Key 余额不足 / 环境被占用 | 先用「自定义」减少轮数；检查余额；先「停止模拟」再重启 |
| 报告生成失败 | 生成过程中断（例如额度用尽） | 重新点「开始生成结果报告」；已写好的章节会保留 |
| 无法和角色对话 | 模拟已结束或环境已关闭 | 回到第 ③ 步重新「开始模拟」，再进入第 ⑤ 步 |
| 页面空白 / 没有反应 | 服务被关掉了 | 回到终端重新执行 `npm run dev`，刷新页面 |

遇到看不懂的报错，把**终端里的那几行文字**和**页面右下角的日志**一起截图去提问，会更容易得到帮助。

## 7. 名词小词典

| 名词 | 白话解释 |
| --- | --- |
| 现实种子 | 你上传的资料 |
| 模拟提示词 | 你写的推演需求 |
| 本体 | 系统从资料里总结出的「有哪些类型的事物」 |
| 知识图谱 | 人物/机构/事件之间的关系网，MiroFish 的长期记忆 |
| Agent（智能体/角色） | 平行世界里的一个「人」，有人设、记忆和行为习惯 |
| 轮次 | 世界里的时间单位，1 轮 ≈ 现实世界的若干分钟 |
| 世界1 / 世界2 | 两个不同风格的社交平台（信息流 / 话题社区） |
| ReportAgent | 负责写报告和答问的「分析师」 |
| 深度互动 | 和角色或分析师对话、发问卷 |

## 8. 数据与隐私（请务必看）

- 你上传的文档内容会**发送给你配置的大模型服务商和 Zep Cloud**，用于生成图谱和报告；它不会上传到 MiroFish 项目组。
- 因此**不要上传机密、违法或他人隐私资料**。
- 所有结果保存在你自己电脑的 `backend/uploads/` 目录里（Git 不会保存它）。删掉这个目录就等于清空全部记录。
- `.env`（含你的 Key）不要发给别人、不要上传到代码仓库。

## 9. 一次典型体验流程（建议照抄）

1. 准备一份 1～3 页的新闻或报告；
2. 提示词写成一句明确的「如果……会怎样」；
3. 第 ① 步等图谱建好；
4. 第 ② 步切到「自定义」，把轮数调到推荐值的 1/3 左右；
5. 第 ③ 步跑完，确认动作流里确实有人在互动；
6. 第 ④ 步生成报告，顺便读一读日志里它引用了哪些事实；
7. 第 ⑤ 步挑 2～3 个角色问一句「你怎么看？」，感受一下平行世界的说服力；
8. 觉得靠谱了，再放大轮数和资料规模重跑一次。

## Appendix · English quick start

1. Install **Node.js 18+**, **Python 3.11–3.12** and **uv**.
2. `cp .env.example .env`, then fill in `LLM_API_KEY` (any OpenAI-compatible endpoint,
   e.g. Alibaba Bailian `qwen-plus`) and `ZEP_API_KEY` (Zep Cloud).
3. `npm run setup:all && npm run dev` (or `docker compose up -d`).
4. Open **http://localhost:3000**, switch the language in the top-right corner.
5. Follow the five steps: upload seed documents + a plain-language prediction question →
   build the graph → generate the environment (reduce the round count for a first try) →
   run the simulation → generate the report → chat with the ReportAgent or any simulated
   agent.

Costs: one typical simulation averages a few US dollars of LLM + Zep usage; both providers
have free tiers for small experiments. Your documents are sent to those providers, so do not
upload material you are not allowed to share. Reports and simulations are stored locally in
`backend/uploads/`.
